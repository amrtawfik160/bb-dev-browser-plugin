# Browser audit — 4 September 2026

The plugin was rebuilt, reloaded, and checked through its live browser tool.
Existing working-tree edits to Origin Scope, script handling, and documentation
were preserved.

## Fixed

- The streamed page now forwards clicks, movement, scrolling, keyboard input,
  explicit text paste, and composition events. Coordinates account for scaling
  and letterboxing. Leaving the page releases held input; Shift+Escape returns
  focus to BB. Spectators and disconnected panels cannot forward input.
- Input sequences start at one so the gateway accepts the first event.
- Chromium receives character text, Enter's newline, and modifier information. Viewport changes
  change page layout as well as capture size.
- Screencast frames use integer sequences and acknowledge Chromium's actual
  frame IDs. The source follows the shared active tab and stops when Chromium
  disconnects. Stream failures close the panel connection for recovery.
- Renderer monitoring tolerates processes disappearing during inspection and
  avoids reading unrelated command lines. Unreadable browser descendants still
  fail closed, and the eight-renderer limit remains enforced.
- Enter on a dialog's Cancel button no longer accepts the dialog. Replacement
  prompts show their own default text.
- Missing profiles produce a schema-valid status response.
- New-tab guidance directs owners to Browser Settings for agent access.
- Copy-address actions write to the displaying client's clipboard and show
  permission failures. The nonfunctional Save image menu item was removed;
  image saving needs Host Download quarantine integration.
- Websites receive the profile's selected language through Chromium's
  `--accept-lang` launch setting. This flag's purpose is documented in
  [Chromium's source](https://chromium.googlesource.com/chromium/src/+/2244d2e5fccead856aa40c3402509b25c3a0ea40/chrome/common/chrome_switches.cc).
- The real authentication fixture uses `window.open`, creates valid isolated
  profiles with the browser user's ownership, resolves the actual helper socket
  location, and cleans up failed workers. Its crash check follows a graceful
  storage checkpoint instead of racing Chromium's asynchronous disk writes.

## Follow-up: overlapping browser calls

Two threads using one Browser Profile produced repeated `browser_busy` errors
while a successful 20-second operation held control. The previous five-second
wait limit caused the failures. Waiting agents now receive control in arrival
order for up to 30 seconds, with cancellation, expiry, and owner takeover still
discarding pending calls. ADR 0005 and the agent guidance record this change.

The updated release gate passed with **884 tests passed and 39 conditionally
skipped**. A live check after reload issued overlapping calls on the same
profile: both succeeded, and the second completed after waiting approximately
12.6 seconds. Regression tests cover a 20-second active operation, serial
execution through the public tool, wait expiry, cancellation, and owner priority.

## Follow-up: disconnected Browser Panel

The panel showed shared tabs but reported “This browser is not connected.”
The corresponding server log showed capability issuance failing because the
machine-only sharing API required a separate machine credential for the BB
server host, although its Connect server tunnel was already connected.

Panel gateways now use Connect's public `expose` RPC with the explicit host ID.
Connect selects the server tunnel or the enrolled remote machine. Shares remain
independent across panels and are removed on panel release, plugin disposal,
or after the authorization lifetime and reclaim window. Returned share URLs
must match the requested host and port and use HTTPS.

The live frame check also exposed an empty tab snapshot after worker reload.
The host now reconciles Chromium's existing tabs before starting capture and
when the panel requests its tab list. A regression test reproduced the empty
snapshot before the fix.

After building and reloading the plugin, a live panel connection issued a
capability, reached authenticated readiness, and delivered three frames. Its
tab snapshot contained the existing active tab. The temporary panel and share
were released. An unauthenticated request to the public share returned 401.
This checks live host streaming and the public authentication gate; it does
not observe the owner's remote client directly.

The final release gate passed with **889 tests passed and 39 conditionally
skipped**, including the server-tunnel and restored-tab regressions.

## Follow-up: shared-profile stability

A thread driving Coolify through `browser_script` failed with "The Browser
Profile has no visible active tab", a `bb browser open` call was refused for
lacking project context, and the owner's Browser Panel showed two tabs while
Chromium had none. The plugin host worker also ran at roughly half a CPU core.
Five causes were found and fixed:

- **Out-of-scope owner tabs were closed and the call denied.** Before each
  agent call the Origin Scope guard closed every open tab outside that agent's
  grant and reported the first one as a denial. With three projects sharing one
  profile under exact-origin grants, each call destroyed the others' tabs and
  the owner's own browsing, leaving the strip with ids Chromium no longer had.
  Those tabs are now parked on `about:blank` for the length of the call and
  restored afterwards; a tab that cannot be parked is still closed. Chromium
  runs with back/forward cache disabled so a parked document cannot be brought
  back without a network navigation the route sees.
- **No fallback when binding `page`.** Under an exact-origin grant the preamble
  only accepted a tab already on that origin and failed otherwise. It now falls
  back to the visible tab, then the first tab, and opens a tab when the profile
  has none. A script that leaves no visible tab no longer fails after
  succeeding.
- **Strip reconciliation gave up without a front tab.** When no page reported
  itself visible, the active-tab read failed and the whole inventory sync was
  skipped, so stale tabs stayed in the panel and owner navigation hit
  `tab_invalid`. The inventory is now applied regardless, and the active-tab
  script brings the first tab forward instead of failing.
- **The renderer monitor scanned every process four times a second.** Counting
  renderers read `/proc/<pid>/stat` for all ~350 host processes every 250 ms.
  It now walks the browser's own subtree through `/proc/<pid>/task/*/children`,
  falling back to the full scan only where the kernel lacks those files.
- **The CLI required `BB_PROJECT_ID`.** Some provider shells forward only
  `BB_THREAD_ID`; `bb browser open` and `script` now read the project from the
  thread in that case and name the missing variable when neither is present.

A QuickJS syntax error (`expecting ','` with no position) now carries a
`Syntax check:` line from Node's parser naming the offending script line.

The release gate passed with **914 tests passed and 39 conditionally
skipped**, including a real-Chromium check that an out-of-scope owner tab is
parked and restored, and the renderer-monitor subtree walk. After reloading
the live plugin, a script against a profile with no tabs opened one and
succeeded, `bb browser open` ran with only `BB_THREAD_ID` set, and the host
worker's `/proc` reads fell from roughly 1,500 to 100 per second.

## Follow-up: Default Access

The owner asked for agents to browse any site without an approval step, after
a thread stalled on `origin_denied` waiting for a grant. A project's first
agent operation on a profile now records a persistent whole-web Profile Grant
and proceeds ([ADR 0015](../adr/0015-grant-agents-the-whole-web-by-default.md)).
The grant is visible and revocable in Browser Settings; revoking it withdraws
Default Access for that project and profile so its agents return to the Grant
Request flow, and granting the whole web again restores it. Lifecycle
revocations leave Default Access in place. Raw localhost, elevations, non-web
navigation, and deleted-project tombstones keep their existing rules. Because
the default scope is the whole web, ordinary agent calls no longer park the
owner's other tabs.

Contract tests that exercise the Grant Request flow now begin by revoking the
project's whole-web grant, which is the owner action that withdraws Default
Access. After reloading the live plugin, a script from a project that had never
been granted a profile ran without approval and left one persistent whole-web
grant for that project and profile in Browser Settings.

## Follow-up: panel and Settings redesign

The Browser Panel and Browser Settings were reworked to feel like first-party
BB surfaces rather than a form with a browser thumbnail. A new
`panel-primitives.tsx` holds buttons, fields, notices, an inline glyph set, and
list-state components, all styled on the host's theme tokens so both surfaces
follow BB's light and dark themes. The host's `attention` color is reserved for
one thing: the frame and toolbar line shown while an agent drives the browser.

Panel changes: toolbar history and options are icon buttons with tooltips; the
tab strip is one horizontally scrolling row instead of wrapping; site-access
questions, dialogs, the context menu, and the downloads shelf are cards and
popovers on host tokens; keyboard, focus, and spectator gating are unchanged.

Settings changes: the single "Host readiness" section became six host-rendered
sections, Browser, Agent access, Profiles, Downloads, Activity, and
Maintenance. Each loads its data on mount with loading, empty, and error
states that name the next action, activity renders as a table, and activity
and diagnostics export as files. Identifiers appear only as secondary
monospace text. The public-plugin harness now stacks every registered settings
section so existing tests query one tree.

The release gate passed with **935 tests passed and 39 conditionally skipped**,
including the new primitive, panel, and settings-section assertions. No server
RPC, contract, authorization, or streaming behavior changed, and `CONTEXT.md`
is untouched. Recorded as [ADR 0014](../adr/0014-translate-domain-vocabulary-at-the-panel-edge.md)'s
presentation boundary; no new ADR was needed.
