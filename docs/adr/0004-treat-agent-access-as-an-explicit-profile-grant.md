# Treat agent access as an explicit profile grant

An authenticated Browser Profile is a privileged capability: owner interaction is available across repositories, but agents are denied until the owner grants an exact BB project identifier access to a specific profile and Origin Scope. That grant covers every provider, thread, environment, and worktree in the project but never follows a copied project; project deletion or manual revocation interrupts automation immediately without closing the owner's page. A denied web-origin operation ends with a typed error and a Grant Request that expires after 15 minutes rather than auto-approval or automatic replay; non-web navigation ends with the typed denial and no request because it has no grantable web origin. The default one-retry authorization expires after five minutes or first use. Exact-origin access may persist, while whole-web, file-transfer, and invalid-certificate access defaults to one hour and needs a second confirmation to persist. An allowed origin confers full automation rather than a misleading read-only promise. HTTP(S) escapes are aborted by the host route before commit, direct agent non-web `Frame.goto` is rejected before its Playwright command reaches Chromium, and renderer-initiated escapes use a CDP fail-closed cleanup guard; ordinary cross-origin subresources may render and cross-origin frames require their own grant.
