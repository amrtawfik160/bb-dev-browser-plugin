# Provision browser hosts explicitly

Browser dependencies are installed through a visible Settings checklist or resumable, idempotent `bb browser setup`, and privileged host changes always require owner confirmation rather than occurring at plugin startup. Version one supports Ubuntu and Debian on x86_64, pins compatible `dev-browser` and Playwright fallback versions, and lets Chrome Stable update through its signed system repository; health checks report incompatible drift but never silently upgrade system packages or remove packages after partial failure. The protected-storage fallback copy first ingests the mutable cache through a descriptor-anchored boundary that accepts only regular files and directories, then copies only the normalized private staging tree across the privileged boundary, applies non-following ownership operations, and never installs a cache-provided setuid sandbox helper; fallback execution remains under `bb-browser` and requires user namespaces or a separately validated system helper. Disable or uninstall stops processes but retains authenticated profiles, while a separate explicit purge owns destructive system-user, configuration, and profile removal. This narrower, controlled setup trades immediate portability for a supportable security boundary and predictable browser compatibility.
