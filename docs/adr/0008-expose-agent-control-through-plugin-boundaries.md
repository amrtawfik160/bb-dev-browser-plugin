# Expose agent control through plugin boundaries

Agents control the Workspace Browser through a statically registered plugin-native `browser_script` tool documented by a bundled skill, while a `bb browser` command provides the equivalent scripted surface and operational diagnostics. The tool accepts a required human-readable purpose shown only during the lease, an optional runtime-only tab identifier, QuickJS-sandboxed Playwright code without Node or filesystem access, and a timeout capped at 30 seconds; structured results are capped at 256 KiB and screenshots must be requested explicitly. Browser Results are ordinary BB thread output that may persist and enter provider context, while the plugin keeps no extra copy. Both paths derive project and host from BB context and enforce Profile Grants, Origin Scopes, time limits, and Control Leases at runtime before delegating execution to `dev-browser`; raw automation endpoints are not the public interface, and authorization changes never require provider restart.
