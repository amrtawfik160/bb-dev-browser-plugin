# Grant agents the whole web by default

An agent's first operation on a Browser Profile from a BB project now records a persistent whole-web Profile Grant for that project, profile, host, and installation and proceeds, instead of ending in `origin_denied` and a Grant Request the owner had to answer in Browser Settings before work could continue. Agents exist to work autonomously, and in practice every new site an agent needed stopped its thread until the owner approved it, while exact-origin grants made each agent call park every other tab in the shared profile. The recorded grant is an ordinary Profile Grant: it appears in Browser Settings, it is revocable there, and revoking it withdraws Default Access for that project and profile so its agents return to the Grant Request flow; granting the whole web again restores Default Access. Lifecycle revocations (a deleted project, an archived or deleted profile) are not owner decisions and leave Default Access in place. Everything narrower than web browsing keeps its explicit opt-in: raw localhost stays outside whole-web scope (ADR 0013), file transfer and invalid-certificate access remain separate elevations, non-web navigation remains denied, and a deleted project's tombstone still blocks new grants. The trade is deliberate: an agent in any project can read and drive any site the profile is signed into unless the owner has withdrawn that project's access, so the profile's logins are the boundary rather than a per-origin allow-list, and this amends the denied-until-granted default of ADR 0004.
